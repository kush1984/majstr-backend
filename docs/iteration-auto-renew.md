# Subscription auto-renewal (monobank card tokenization, V40)

- **Status:** 🔨 Backend code complete; `./gradlew build` pending at the gate. V40
  migration **drill PASSED**. PWA verified: **tsc + vitest(62) + vite build green**.
- **Migration:** `V40__add_auto_renew.sql`.
- **Goal (user, 2026-07-03):** Flip the default from "remember to pay" (churn) to
  "forget about paying" (retention). At checkout the master opts in; the card is
  tokenized; a scheduled job charges it before the period ends. Trust-first: explicit
  opt-in, T-3 warning email, one-tap cancel, retries within grace, no surprise charge.

## monobank API (verified against the official docs, not memory)

- **Tokenize:** `invoice/create` + `saveCardData: { saveCard: true, walletId }` (walletId
  generated by us). Response `{ invoiceId, pageUrl }`.
- **Read token:** `GET /api/merchant/wallet?walletId` → `{ wallet: [ { cardToken,
  maskedPan, country } ] }`.
- **Charge:** `POST /api/merchant/wallet/payment` → `{ cardToken, amount, ccy,
  initiationKind: "merchant", webHookUrl, paymentType: "debit" }`. Result arrives via
  the **same invoice-status webhook** → reuses `handleWebhook` + `invoice_id` idempotency.

## Backend

- **V40:** `users.auto_renew` / `card_token` (sensitive, never in API/logs — excluded
  from `User#toString`) / `card_mask` (display) / `wallet_id` / `renew_reminder_sent_at`;
  `payments.kind` (CHECKOUT | AUTO_RENEW, existing backfilled CHECKOUT).
- **Opt-in checkout** (`CheckoutRequest{autoRenew}`): a fresh `walletId` marks the
  checkout as "save the card". On the success webhook, if `walletId` set + no token yet,
  `firstWalletCard` fetches the token + mask and turns auto-renew on. A plain checkout
  (no opt-in) is unchanged.
- **`AutoRenewService` `@Scheduled`** (daily, before the downgrade job): (1) one T-N
  reminder email per cycle (`renewReminderSentAt` dedup, cleared on every extension);
  (2) charge due subscriptions (expired but in grace) via the token, **one attempt/day**,
  skipping while a PENDING attempt awaits its webhook; a "update card" email after the
  first failure; when grace runs out the existing downgrade job FREEs them **and clears
  auto-renew** so a dead card is never hammered.
- **Trust / safety:** explicit opt-in; token never logged/returned (only `cardMask` +
  `autoRenew` in `UserResponse`); disable is one tap (`PATCH /api/profile/auto-renew`,
  instant, keeps the token); idempotent on `invoice_id`; one cycle → at most one
  extension (webhook extends from `max(now, expires)` only on the first success);
  dev-simulation covers the whole flow (fake token) without a merchant account.
- **Emails** (`ResendEmailService`, env-gated, `@Async`, fail-soft): T-3 reminder,
  receipt, failed-with-update-card.
- **Admin:** per-user auto-renew state + masked card + last auto-charge outcome; overview
  "auto-renew users" (MRR signal); payments carry `kind`.
