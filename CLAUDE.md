# Majstr Backend — Claude guide

SaaS backend for Ukrainian contractors: auth, projects, clients, catalog, estimates (PDF + public
client portal with online signing), subscriptions/admin, email verification, web push, monitoring.
[README.md](README.md) has end-user setup and the public REST contract; this file is for contributors.

**This file is deliberately short (it loads every session) — keep it that way.** Every bullet of the
Architecture index has an unabridged twin in
**[docs/architecture-index-detail.md](docs/architecture-index-detail.md)**, paired by title: put the
reasoning THERE and the invariant here. Per-area narrative lives in
**[docs/architecture.md](docs/architecture.md)** — read the relevant section before working in that
area. History: `docs/iteration-*.md`; deferred decisions: [docs/open-questions.md](docs/open-questions.md).

[docs/architecture-index-2026-10-04.md](docs/architecture-index-2026-10-04.md) for a name an old

## Stack (pinned)

- **Spring Boot 4.0.6** (Spring Framework 7, Jakarta EE 11) on **Java 21 (LTS)**
- **Gradle Kotlin DSL** — toolchain pinned to JDK 21 in `build.gradle.kts`
- **PostgreSQL 17** via `docker-compose.yml`, schema owned by **Flyway**
- **Spring Security 7**, stateless, JWT via **jjwt 0.12.x** (HS256)
- **Bucket4j 8.x** — login rate limiting
- **Jackson 3** — package is `tools.jackson.*`, not `com.fasterxml.jackson.*` (see index → Gotchas)
- **Lombok**, **springdoc-openapi 2.8.x**, **JUnit 5 + MockMvc**

Don't bump these without a clear reason — the combo is chosen for Spring Boot 4 / Spring 7 / Jakarta
EE 11 / Java 21 compatibility. (Java 21 over 25: Java 25 had no reliable build image on Railway.)

## Common commands

```bash
docker compose up -d   # Postgres (needs .env with POSTGRES_PASSWORD)
./gradlew bootRun      # run the app (env vars from .env must be exported)
./gradlew build        # full build with verification (./gradlew test = tests only)
```

JWT secret and DB credentials come from **env vars only** — never hardcode; the base
`application.yml` references `${JWT_SECRET}` with no default and startup fails fast without it.

## Package layout

```
com.majstr.backend
├── config/ controller/ repository/ entity/ dto/   — the usual; controllers are thin
├── service/                   — business logic, @Transactional boundaries
│   ├── ai/                    — LLM provider plumbing (per-flow provider/model)
│   ├── album/                 — full-album takeoff: surfaces + electrical (built, NOT exposed)
│   ├── importer/              — estimate / receipt / catalog import from file or photo
│   ├── fiscal/                — fiscal-QR decode + ДПС lookup
│   └── measurement/           — measurement domain + project-document import
├── security/                  — JwtService, filters, UserPrincipal, body-cache wrapper
├── feature/                   — plan gates: Feature/Limit enums, PlanConfig, guards
├── billing/  storage/         — monobank checkout + auto-renew / local + S3-R2
├── email/  push/              — Resend HTTP client + templates / Web Push (VAPID)
├── bootstrap/  dev/           — startup seeding / @Profile("dev") only
└── exception/                 — typed exceptions + GlobalExceptionHandler
```

Layering rule: `controller → service → repository`. Entities never leave the service layer —
controllers return DTOs. `passwordHash` never appears in any response (`UserResponse` excludes it;
`User#toString` excludes it).

## Schema (Flyway)

`hibernate.ddl-auto: validate` — never express schema changes in entity annotations. Add a new
`V<N>__<desc>.sql` under `src/main/resources/db/migration/`; **check the highest number first**
(latest is **V147**). **Never edit an applied migration** — Flyway checksums it and a changed file
fails startup (a correction to a shipped migration's COMMENT goes in the next migration's header —
review B-53 did that for V136). **A self-check may `RAISE EXCEPTION` only about the migration's OWN
work** (review B-50): «I just re-filed these rows, assert none is left» is a bug if it fails, while
«every shipped norm still finds a catalog position» is about data an admin can rename between two
deploys — that one is a `RAISE WARNING`, and the integration tests are what keep it honest in CI. New `Trade` enum constant → migration to extend the `user_trades` CHECK (a
master-invented trade instead goes in `user_trade`, no migration needed).

## Testing

Spring Boot 4 removed all test-slice annotations (`@WebMvcTest`, `@DataJpaTest`, …). Two patterns:

1. **Controller tests** — pure Mockito (`@ExtendWith(MockitoExtension.class)` + `@Mock`/`@InjectMocks`
   + `MockMvcBuilders.standaloneSetup(controller)`, register `GlobalExceptionHandler` via
   `.setControllerAdvice(...)`). No Spring context, no DB.
2. **Integration tests** — full `@SpringBootTest` against a **Testcontainers** Postgres via
   `IntegrationTestBase` (`@ActiveProfiles("test")`). **Docker is required to build** (they fail, not
   skip). Use for anything Mockito can't see: a migration applying, a `nativeQuery`/`@Query`, a CHECK
   constraint, the security filter chain end to end. Name `…IntegrationTest`, **not** `…IT`.

`application-test.yml` holds the test JWT secret and the settings that slice loads.

## Conventions

- **Language**: all code, comments, logs, SQL, YAML, Markdown — **English only**; the user chats in
  Ukrainian but artifacts stay English.
- **Comments**: default to none; a one-liner only when the *why* is non-obvious. Don't restate code.
- **A catalog position names the WORK and its RESULT, never a brand** («Каталог описує роботу і
  результат, а не бренд») — no manufacturer, product name or system code (Knauf C112 / W623 / D112)
  in a `catalog_templates` name. A standard may be cited in a `description`; a brand may not name a job.
- **Boundaries of change**: keep changes scoped. Bug fix ≠ refactor. No abstractions for hypothetical
  future needs. **No backwards-compat shims** for code that hasn't shipped — greenfield, just change it.
- **Tests + green build before push (hard gate)**: every change updates/adds tests, and **Claude runs
  `./gradlew build` itself** (~2-3 min; Testcontainers and Docker work). Only push on green — never
  push red, never report green without a run. Red → fix to green first.
- **PWA gate = MIRROR CI's `verify` job, in order** (`majstr-pwa/.github/workflows/ci.yml`):
  `npm run lint` → `npx tsc -b` → `npm run typecheck:tests` → `npx vitest run` → `npx vite build`.
  Two are easy to forget and each has reddened CI alone: **`npm run lint`** (`eslint --max-warnings 0`
  — a stray `!`/`as` is a HARD error) and **`npm run typecheck:tests`** (a SEPARATE, stricter tsconfig
  covering the TEST files, which `tsc -b` does **not**). "build + vitest were green" is NOT the gate.
- **Offline/service-worker changes also need `npm run test:e2e:offline`** (CI runs the shell spec).
  The normal e2e runs on the Vite dev server where the SW is DISABLED, so no dev-based test sees an
  SW regression. Verify a new one fails without the fix — check the SOURCE, not minified `dist/sw.js`.

## Not implemented yet (don't claim these exist)

- No multi-instance rate-limit store (in-memory `ConcurrentHashMap`).
- No in-app reply to a client message — the inbox is one-way by design; the master follows up out-of-band.
- No offline photo upload **except act receipts** (PWA-only) — progress photos and the estimate-side receipt import are still online-only; the general blob outbox (offline follow-up O6) stays open.
- No TEAM multi-user workspaces; TEAM is a plan, not a shared workspace yet.
- Full list of deferred decisions: [docs/open-questions.md](docs/open-questions.md).

## Architecture index

Each bullet keeps **the invariant and the identifiers, not the reasoning** — one to three lines. The
unabridged long form of every one is [docs/architecture-index-detail.md](docs/architecture-index-detail.md),
paired by title; **when you are about to change something a bullet warns about, read the long form
there first**, then the doc it names.

- **Auth flow** — register/login/refresh/logout/me; `LoginRateLimitFilter` precedes `JwtAuthenticationFilter`.
- **FREE object cap counts LIFETIME creations (V107)** — `users.lifetime_project_count` is the basis; `LimitService.reserveProjectSlot` locks + increments in one tx, a delete never decrements, idempotency check first. `PlanLimitsResponse.projectsUsed` = lifetime, NOT the live list length.
- **Refresh tokens** — hashed at rest (SHA-256), rotated, swept daily; **the PWA must single-flight `/refresh`** or a burst of 401s self-logs-out.
- **Email verification is soft** — `@Async` fail-soft; only `POST /estimates/{id}/share` is gated (403 `EMAIL_NOT_VERIFIED`); email editable only while unverified.
- **Web push** — VAPID, `@Async`, env-gated fail-soft; `deliver()` MUST pass `Encoding.AES128GCM` (legacy `aesgcm` → FCM 403).
- **Client portal is project-level** — `project_share_links` token + `estimates.portal_visible`; `payments_visible` (V93, default false) gates the payments card. **The per-estimate `?t=` link is NOT legacy** — it is the single-estimate share path and never touches the object portal. `ShareLinkService.create` is idempotent; an **expired** link is replaced (the repo query filters only `revoked`).
- **Client messages** — one-way inbox (renamed from "questions", V74); entity field `read` vs view JSON key `isRead`; message-link + attachments + 6-month retention (V75-77).
- **Login rate limit** — `CachedBodyHttpServletRequest`; key `email|ip`; in-memory, single-node. **All eleven limiters share `BucketRegistry<K>`** (B-22) — six are keyed by something a STRANGER picks, so an entry idle for twice its own refill period is dropped (unobservable: the bucket is full by then).
- **Signed estimates are immutable** — mutate/delete → 409 `ESTIMATE_SIGNED`; owner-only `reopen` (behind `REOPEN_ENABLED = false`); `@Version` (V23). **A signed parent is NOT auto-reopened when its duplicate is signed** — `doSign` sets `parent.countInEconomy = false` and stamps `estimates.superseded_by_estimate_id` (V95); cleared on edit (`requireNotSigned`, the one guard all 8 write paths share), re-sign or dismiss.
- **Work acts (`work_act`/`work_act_item`, V104)** — built from a signed estimate, signed separately; all line fields are **frozen copies**, estimate FKs `ON DELETE SET NULL`. One open (DRAFT/SENT) act per object (409 `WORK_ACT_OPEN`); a FINAL act closes it (409 `WORK_ACT_FINAL_EXISTS`); signed = immutable; delete only DRAFT/REJECTED. **Numbering is continuous per master** (`UNIQUE(user_id, number)`), so `create()` is non-`@Transactional` and retries `WorkActCreator.attempt`. **Progress is never denormalized** — Σ over SIGNED acts (`sumSignedQuantitiesByEstimateItem`). Off-estimate lines become a SIGNED, counted, non-shared `Estimate.kind = ADDENDUM`. **«Новий акт» creates NOTHING** — `/acts/new` is a static route; `persist()` is the one door.
- **Act portal (`ShareLinkKind.ACT`, `?a=`, V105)** — a fourth link kind, deliberately NOT folded into read-only ECONOMY; one link = one act (`project_share_links.work_act_id` + CHECK). **Only SENT/SIGNED are served** — a DRAFT is 404 even with a valid token. Sign records signer name/phone/ip/UA, stamps SIGNED, computes **`doc_hash` = SHA-256 of the canonical (unstamped) PDF**, pushes + emails fail-soft. Wording is «Підтвердити приймання робіт», never a legal-equivalence claim.
- **Works axis in economy (FREE-visible)** — `ObjectEconomyResponse.acts(contracted, acceptedByActs, received)`, computed unconditionally. **INVARIANT — numerator and denominator count ONE estimate set**: `sumSignedActLineTotals` and `sumIncomeCounted` both take only SIGNED + `count_in_economy = true` estimates **plus off-estimate lines (`estimate_id IS NULL`)**, so «Прийнято актами» ⊆ «За договором». Enforced three ways: `progress` skips `!countInEconomy`, a write guard (400 `WORK_ACT_ESTIMATE_EXCLUDED`), and both sign paths using `ActAddendumCreator`. **Never drop the `IS NULL` branch or the `count_in_economy` filter.** An ADDENDUM panel carries no ⋮ (409 `ESTIMATE_ADDENDUM_LOCKED`).
- **The economy progress strip is ONE component in THREE places (green-progress-strip)** — **colour is a POSITION, never a verdict**: the gradient spans the whole TRACK (`background-size: {(100/pct)*100}% 100%` on a `width: {pct}%` fill); drop the `background-size` and you get the rejected hue interpolation. 100 % is a separate solid state. `components/ProgressStrip.tsx` + **the portal's hand-copied rule in `static/portal/index.html`** — mirrored pair, change one change the other. `progressPct()` is **uncapped** (only the width clamps). [docs/iteration-green-progress-strip.md](docs/iteration-green-progress-strip.md).
- **Act «ДОВІДКОВО» reference block (V106)** — three object-wide money rows from the works-axis queries via `ActCumulativeCalculator`. **Default OFF**, shown from the 2nd act, and **excluded from the canonical (hashed) render** (`PdfModel.cumulative = null` at hash time) — a later signing must never invalidate an earlier act's `doc_hash`.
- **Acts follow-ups (acts-improvement, V108 `work_act.title`)** — optional `title`, frozen on sign; owner status moves `PATCH /api/acts/{id}/status`, allowed set ONLY `SENT→DRAFT` / `SENT→REJECTED` / `REJECTED→DRAFT` (else 409 `WORK_ACT_BAD_TRANSITION`); `ActSignedCopyService` shares the docHash stamp + client PDF across BOTH sign paths; `QuestionRateLimiter` is separate from the 30/min `PortalRateLimiter`.
- **Act receipts — «Чеки та рахунки» (V110 + V111)** — `work_act_receipt` + `work_act.receipts_to_expenses`. **The photo is MANDATORY** (400 `WORK_ACT_RECEIPT_PHOTO_REQUIRED`); all writes behind `requireNotSigned`; `payable` = `total` + receipts − `advanceOffset`, floored at 0. **The ⊆ invariant extends to them** — on sign they join the ADDENDUM and `sumSignedActReceipts` feeds `acceptedByActs`. Recognition (`AiFlow.ACT_RECEIPT`) is free, persists nothing, is **not `@Transactional`**. **`itemized` is LEGACY and still load-bearing** — every `AND r.itemized = false` STAYS or money is billed twice. The PDF receipts block is **inside** the hashed render. **A new LLM verb must join `api/client.ts`'s long-timeout rule.** `update` refuses amount 0 while SENT; `add` still accepts 0 (the batch state, and what an offline queue replays).
- **Fiscal QR fast path (`service/fiscal/`)** — `FiscalQrService.read` is a ladder that **degrades, never fails**: no payload → not recognized; ДПС unreachable → recognized on total + date; positions not summing to `sm` within **0.02** → dropped wholesale, meta kept. `FiscalCheckXml` tolerates `ROW`/`P` and is XXE-hardened; blank `app.fiscal-qr.base-url` = lookup disabled. **Everything the QR returns is FREE** (no `RECEIPT_IMPORT` gate on `commit`). Two live-paper traps: `RestClient.uri(String)` re-encodes an encoded URI (**build a `URI` with `.encode().build().toUri()`**), and positions read `CHECKBODY` → bare `<P>`. [docs/iteration-fiscal-qr.md](docs/iteration-fiscal-qr.md).
- **Receipts arrive as a BATCH — saved first, priced later (receipts-batch)** — `MIN_AMOUNT` is **0**, so an unpriced receipt is a legal state; what makes it safe is **`ActReceiptCompleteness.requireAllPriced` on all three doors** — publish, `signOffline` AND `PublicActPortalService.sign` (the portal one is NOT redundant: receipt writes are governed by not-SIGNED, not not-SENT). A blank label is named **«Чек №N» by the SERVER**; the add endpoint takes **`X-Entity-Uuid`** plus optional `fiscalFn`+`fiscalId` (together or not at all); **`findByWorkActIdNewestFirst` at EVERY call site** so editor/PDF/portal/ADDENDUM agree on which receipt is «1.»; `recognize` reads the STORED photo; **`QrScanRateLimiter` counts the QR path apart**. [docs/iteration-receipts-batch.md](docs/iteration-receipts-batch.md).
- **Partial returns on an act receipt (V115)** — `work_act_receipt.returned_amount` (CHECK `>= 0 AND <= amount`); no return document. `amount` stays what the PAPER says and everything downstream reads **`billedAmount() = amount − returnedAmount`** (`receiptsTotal`/`payable`, `sumSignedActReceipts`, `sumByWorkActId`, the posted `ObjectExpense`) — change one without the others and the bill, «Прийнято актами» and `Прибуток` disagree. The ADDENDUM list filters `billedAmount().signum() > 0`; the EXPENSE list stays unfiltered. **`work_act.advance_offset` is DOCUMENT-ONLY.** [docs/iteration-act-receipt-returns.md](docs/iteration-act-receipt-returns.md).
- **Admin funnel's `shared` step = BOTH link tables (analytics-shared-fix)** — a **union of owner-id SETS** (`findSharedOwnerIds`), never a sum of two `COUNT(DISTINCT)`s. `ShareLinkKind.SHARED_WITH_CLIENT` = {PORTAL, ECONOMY, ACT} is the one classification point; **`MESSAGE` excluded**, **`revoked`/`expires_at` NOT filtered**, every step filters `role = USER`; historical figures are understated.
- **By-source funnel + first-touch UTM (V114)** — the funnel per source, whose `shared` is **the same computation as the aggregate, not a copy** (`sharedOwnerSources()` once; the funnel takes `.size()`). **Invariant pinned by `SourceBreakdownIntegrationTest`: for every step, Σ over sources == the `ActivationFunnelResponse` field.** Below `SIGNIFICANT_SOURCE_MIN_REGISTRATIONS` (5) a row is grouped under «замало даних»; the SERVER owns row order. **UTM is the CHANNEL dimension, `referral_source` the PARTNER one** — `users.utm_*` stamped ONCE at registration, never overwritten, and **NULL is a legitimate value** («без UTM», hence the deliberate `HashMap`). [docs/iteration-analytics.md](docs/iteration-analytics.md).
- **PostHog is PWA-only, and the boundary is a rule (iteration-posthog)** — **money and state belong to the backend; PostHog only gets what the backend does not already write** (which killed `checkout_started`/`estimate_signed`, and is why the two **dictation** events are legitimate — never the spoken text, only counts). The **privacy policy is part of the feature**; **no personal data leaves the device** (`autocapture:false`, a fixed five-property set); consent is one door, `applyAnalyticsIdentity(me)`; **`reset()` on logout is mandatory** (a crew shares one phone). **The one BACKEND consequence is the replay→person join** — `UserRepository.idOrNull` ORs `u.id = :id` into **both** ordering queries by **equality, never LIKE**, and requires the canonical 36-char form (`UUID.fromString` is LENIENT below it). [docs/iteration-posthog.md](docs/iteration-posthog.md).
- **The PWA update banner needs THREE things, any one silently kills it (iteration-sw-update-banner)** — `registerType: 'prompt'` + a `SKIP_WAITING` handler in `src/sw.ts` (`injectManifest`) + `clients.claim()` on activate. `src/lib/swUpdate.test.ts` asserts all three by **READING `vite.config.ts` and `src/sw.ts` as text** — every mocked test stayed green through a year of it being broken.
- **An act receipt authors offline (offline-act-receipts, PWA-only)** — the op carries the photo as **bytes, not a `Blob`** (`QueuedFile`), downscaled before queueing. Outbox entity `actReceipt`, **create only**, replayed under the same `X-Entity-Uuid`. **Editing or deleting a queued receipt is not a second op** — the pending create is rewritten in place. Queued rows merge into the server list at ONE point (`ActEditorPage`), **never into the query cache**. Trap: `initOutbox` also subscribes to reconnects — call it ONCE.
- **Dictation is text, never audio** — `AiFlow.DICTATION` + `POST /api/estimates/{id}/dictation/{parse,commit}`; we record and transcribe nothing. **A position matching nothing in the master's `catalog_items` comes back FLAGGED (`issues` gains `"catalog"`), never silently priced at 0 ₴.** Spoken values win, the catalog fills blanks. **The catalog is deliberately NOT in the prompt** — `CatalogMatcher` decides: exact, then Dice over **4-letter** stems, `MIN_SCORE = 0.6` **and** `MIN_MARGIN = 0.1`, **a tie is refused**. Own hourly bucket; **model PINNED to `claude-sonnet-5`**; ungated on purpose; `commit` goes through `appendItems`. [docs/iteration-dictation.md](docs/iteration-dictation.md).
- **The shopping list is where the material answer lands (V126)** — OBJECT-scoped, FREE, **no price**. **A norm has NO foreign key**: `material_norm` is keyed by **name + unit** (`NameKeys`), `trade` is **not part of the key but IS a filter on the answer**, a norm's unit is read off the POSITION and never converted, and `material` has **no price and no owner** (V81). **The list never writes an `ObjectExpense`.** A recalculation replaces its OWN contribution via `source_estimate_id`; `clearBought` and a SETTLED row's `delete` **hide** (`cleared_at`); a hand-typed quantity parks ours in `suggested_quantity` (V128). `topUp` is derived on the read path, so `render()` loads **every** row. Rows are **never merged**. **An unsigned source estimate is a HINT, never a gate.** [docs/iteration-shopping-list.md](docs/iteration-shopping-list.md).
- **The calculator answers «скільки купити» (V127)** — turns one estimate's WORK lines into materials, FREE. Four invariants: the lookup is **keyed by name+unit and FILTERED by the POSITION's trade** (a trade-less norm answers for anyone); **a norm's unit is read off the POSITION and nothing is converted**; a `PERCENT` line and a material the master already listed enter **neither numerator nor denominator** of coverage; a `PERIMETER` norm is **asked for, never derived**. **«Consumes nothing» is a RECORDED verdict** — 11 norms carry `material_id IS NULL`. Rounding runs **UP**. Nothing is stored: the GET recomputes. The Testcontainers schema is SHARED, so `MaterialNormLookupIntegrationTest` must clean up. [docs/iteration-material-calculator.md](docs/iteration-material-calculator.md) §20.
- **TILING + PAINTER norms, and the habits nothing was reading (V137, V138, V139)** — `master_material_pref` held SIX keys and the calculator read TWO, with no screen calling `/api/me/material-prefs`: **a stored preference needs a reader AND a door in the round it gets a column.** The two surviving keys rescale LINEARLY in `coefficient()` — **the SCALED figure is what the arithmetic line shows**, and **an owned norm is never rescaled**. Fourth `NormBasis` **THICKNESS**, asked **per POSITION**; **`sections` and `thicknesses` are TWO query params, never one map**; `default_param` + `MissingParameter.suggested` are **pre-filled VISIBLY, never applied silently**. Shared positions are **re-filed to `trade = NULL`, never duplicated**. [docs/iteration-material-calculator.md](docs/iteration-material-calculator.md) §27.
- **An ANSWER the calculator asked for belongs to the estimate, not the browser (V142)** — `estimate_material_param` is keyed by (position, basis), NOT a column on `estimate_items`: one line can be asked BOTH a SECTION and a THICKNESS, and `estimates` carries the `@Version` the portal sends — hence **no `requireNotSigned`**. The perimeter's row is the one with `estimate_item_id IS NULL`; a CHECK pairs basis with position; TWO PARTIAL unique indexes. **Zero is not an answer** — `value > 0`, a cleared field DELETES the row. `PUT …/materials/params` is a **PATCH, one card at a time**. The GET's query string is **not a second source of truth**: it wins PER QUESTION and the stored set fills the rest. `MaterialParamService` holds repositories ONLY (else a constructor cycle with `EstimateService`). [docs/iteration-material-calculator.md](docs/iteration-material-calculator.md) §29.
- **A coefficient is the MASTER's, and it forks on write** — V126 put `owner_id` INSIDE `ux_material_norm`, so his row sits beside the default it hides (two ITs pin that; "tidying" the constraint 500s an ordinary save). `MaterialNormService.saveOwn` is the one door: it COPIES the shipped norm and never writes the shared row, so **the answer carries the id the write LANDED on**, and **it looks for an existing fork by natural key first**. DELETE restores the default through either id; `material_id IS NULL` is refused 400 `MATERIAL_NORM_INVALID`. **Resolution is a read-path collapse, NOT a second lookup** — `findAllByNameKeysForOwner` + `preferOwn`, order preserved. [docs/iteration-material-calculator.md](docs/iteration-material-calculator.md) §21.
- **A receipt at the till is a RECEIVABLE, not a cost (V129 «Чеки обʼєкта»)** — `project_receipt` is OBJECT-scoped, FREE, `reimbursable` defaults **TRUE** and writes **nothing** to `object_expenses`; only «це моя витрата» posts one into `expense_id` (CHECK `expense_id IS NULL OR reimbursable = false`), and flipping back deletes it. **The materials axis is its OWN FREE-visible axis** — **never fold it into `contracted`/`acceptedByActs`**; a receipt joins the contract only when an act picks it up. Deliberately a SECOND table beside `work_act_receipt`; otherwise the receipts-batch shape verbatim. **`fiscal_fn`+`fiscal_id` are a WARNING, never a unique index**; `PATCH`'s `reimbursable` is **three-valued**; `…/materials/availability` asks about **NAMES, never quantities** (fix O); the shopping-list PDF has **no prices**. [docs/iteration-object-receipts.md](docs/iteration-object-receipts.md).
