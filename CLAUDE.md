# Majstr Backend — Claude guide

SaaS backend for Ukrainian contractors: auth, projects, clients, catalog, estimates (PDF + public
client portal with online signing), subscriptions/admin, email verification, web push, monitoring.
[README.md](README.md) has end-user setup and the public REST contract; this file is for contributors.

**This file is deliberately short (it loads every session).** Non-obvious notes and gotchas live in
**[docs/architecture.md](docs/architecture.md)** and, per index bullet, in
**[docs/architecture-index-detail.md](docs/architecture-index-detail.md)** — read the relevant section
before working in that area. History: `docs/iteration-*.md`; deferred decisions:
[docs/open-questions.md](docs/open-questions.md).

## Stack (pinned)

- **Spring Boot 4.0.6** (Spring Framework 7, Jakarta EE 11) on **Java 21 (LTS)**
- **Gradle Kotlin DSL** — toolchain pinned to JDK 21 in `build.gradle.kts`
- **PostgreSQL 17** via `docker-compose.yml`, schema owned by **Flyway**
- **Spring Security 7**, stateless, JWT via **jjwt 0.12.x** (HS256)
- **Bucket4j 8.x** — login rate limiting
- **Jackson 3** — package is `tools.jackson.*`, not `com.fasterxml.jackson.*` (see index → Gotchas)
- **Lombok**, **springdoc-openapi 2.8.x**, **JUnit 5 + MockMvc**

Don't bump these without a clear reason — the combo is chosen for Spring Boot 4 / Spring 7 / Jakarta
EE 11 / Java 21 compatibility. (Java 21 over 25: Java 25 had no reliable build image on Railway.)

## Common commands

```bash
docker compose up -d   # Postgres (needs .env with POSTGRES_PASSWORD)
./gradlew bootRun      # run the app (env vars from .env must be exported)
./gradlew build        # full build with verification (./gradlew test = tests only)
```

JWT secret and DB credentials come from **env vars only** — never hardcode; the base
`application.yml` references `${JWT_SECRET}` with no default and startup fails fast without it.

## Package layout

```
com.majstr.backend
├── config/ controller/ repository/ entity/ dto/   — the usual; controllers are thin
├── service/                   — business logic, @Transactional boundaries
│   ├── ai/                    — LLM provider plumbing (per-flow provider/model)
│   ├── album/                 — full-album takeoff: surfaces + electrical (built, NOT exposed)
│   ├── importer/              — estimate / receipt / catalog import from file or photo
│   ├── fiscal/                — fiscal-QR decode + ДПС lookup
│   └── measurement/           — measurement domain + project-document import
├── security/                  — JwtService, filters, UserPrincipal, body-cache wrapper
├── feature/                   — plan gates: Feature/Limit enums, PlanConfig, guards
├── billing/  storage/         — monobank checkout + auto-renew / local + S3-R2
├── email/  push/              — Resend HTTP client + templates / Web Push (VAPID)
├── bootstrap/  dev/           — startup seeding / @Profile("dev") only
└── exception/                 — typed exceptions + GlobalExceptionHandler
```

Layering rule: `controller → service → repository`. Entities never leave the service layer —
controllers return DTOs. `passwordHash` never appears in any response (`UserResponse` excludes it;
`User#toString` excludes it).

## Schema (Flyway)

`hibernate.ddl-auto: validate` — never express schema changes in entity annotations. Add a new
`V<N>__<desc>.sql` under `src/main/resources/db/migration/`; **check the highest number first**
(latest is **V133**). **Never edit an applied migration** — Flyway checksums it and a changed file
fails startup. New `Trade` enum constant → migration to extend the `user_trades` CHECK (a
master-invented trade instead goes in `user_trade`, no migration needed).

## Testing

Spring Boot 4 removed all test-slice annotations (`@WebMvcTest`, `@DataJpaTest`, …). Two patterns:

1. **Controller tests** — pure Mockito (`@ExtendWith(MockitoExtension.class)` + `@Mock`/`@InjectMocks`
   + `MockMvcBuilders.standaloneSetup(controller)`, register `GlobalExceptionHandler` via
   `.setControllerAdvice(...)`). No Spring context, no DB.
2. **Integration tests** — full `@SpringBootTest` against a **Testcontainers** Postgres via
   `IntegrationTestBase` (`@ActiveProfiles("test")`). **Docker is required to build** (they fail, not
   skip). Use for anything Mockito can't see: a migration applying, a `nativeQuery`/`@Query`, a CHECK
   constraint, the security filter chain end to end. Name `…IntegrationTest`, **not** `…IT`.

`application-test.yml` holds the test JWT secret and the settings that slice loads.

## Conventions

- **Language**: all code, comments, logs, SQL, YAML, Markdown — **English only**; the user chats in
  Ukrainian but artifacts stay English.
- **Comments**: default to none; a one-liner only when the *why* is non-obvious. Don't restate code.
- **A catalog position names the WORK and its RESULT, never a brand** («Каталог описує роботу і
  результат, а не бренд») — no manufacturer, product name or system code (Knauf C112 / W623 / D112)
  in a `catalog_templates` name. A standard may be cited in a `description`; a brand may not name a job.
- **Boundaries of change**: keep changes scoped. Bug fix ≠ refactor. No abstractions for hypothetical
  future needs. **No backwards-compat shims** for code that hasn't shipped — greenfield, just change it.
- **Tests + green build before push (hard gate)**: every change updates/adds tests, and **Claude runs
  `./gradlew build` itself** (~2-3 min; Testcontainers and Docker work). Only push on green — never
  push red, never report green without a run. Red → fix to green first.
- **PWA gate = MIRROR CI's `verify` job, in order** (`majstr-pwa/.github/workflows/ci.yml`):
  `npm run lint` → `npx tsc -b` → `npm run typecheck:tests` → `npx vitest run` → `npx vite build`.
  Two are easy to forget and each has reddened CI alone: **`npm run lint`** (`eslint --max-warnings 0`
  — a stray `!`/`as` is a HARD error) and **`npm run typecheck:tests`** (a SEPARATE, stricter tsconfig
  covering the TEST files, which `tsc -b` does **not**). "build + vitest were green" is NOT the gate.
- **Offline/service-worker changes also need `npm run test:e2e:offline`** (CI runs the shell spec).
  The normal e2e runs on the Vite dev server where the SW is DISABLED, so no dev-based test sees an
  SW regression. Verify a new one fails without the fix — check the SOURCE, not minified `dist/sw.js`.

## Not implemented yet (don't claim these exist)

- No multi-instance rate-limit store (in-memory `ConcurrentHashMap`).
- No in-app reply to a client message — the inbox is one-way by design; the master follows up out-of-band.
- No offline photo upload **except act receipts** (PWA-only) — progress photos and the estimate-side receipt import are still online-only; the general blob outbox (offline follow-up O6) stays open.
- No TEAM multi-user workspaces; TEAM is a plan, not a shared workspace yet.
- Full list of deferred decisions: [docs/open-questions.md](docs/open-questions.md).

## Architecture index

Each bullet is compressed: it keeps the invariant and the identifiers, **not** the reasoning. The
unabridged version of every one is `docs/architecture-index-detail.md` — **when you are about to
change something a bullet warns about, read the long form there first**, then the doc it names.

- **Auth flow** — register/login/refresh/logout/me; `LoginRateLimitFilter` precedes `JwtAuthenticationFilter`.
- **FREE object cap counts LIFETIME creations, not live rows (V107)** — `users.lifetime_project_count` is the basis, so deleting an object can't slip past the cap; `LimitService.reserveProjectSlot` locks the user and increments in the same tx, a delete never decrements, the idempotency check runs first. `PlanLimitsResponse.projectsUsed` = lifetime, NOT the live list length. Permanent delete is offered only on a terminal object.
- **Refresh tokens** — hashed at rest (SHA-256), rotated (old revoked on use), swept daily; **the PWA must single-flight `/refresh`** or a burst of 401s self-logs-out.
- **Email verification is soft** — `@Async` fail-soft; only `POST /estimates/{id}/share` is gated (403 `EMAIL_NOT_VERIFIED`); email editable only while unverified.
- **Web push** — VAPID, `@Async`, env-gated fail-soft; `deliver()` MUST pass `Encoding.AES128GCM` (legacy `aesgcm` → FCM 403).
- **Client portal is project-level** — `project_share_links` token + `estimates.portal_visible`; `payments_visible` (V93, default false) independently gates the payments card. **The per-estimate `?t=` link is NOT legacy** — it is the single-estimate share path: sharing from one estimate's editor mints/reuses that estimate's own link and never touches the object portal, so a sibling can't be silently dropped off a link already sent. `ShareLinkService.create` is idempotent, and an **expired** link is replaced (the repo query filters only `revoked`).
- **Client messages** — one-way inbox (renamed from "questions", V74); entity field `read` vs view JSON key `isRead`; message-link + attachments + 6-month retention (V75-77).
- **Login rate limit** — `CachedBodyHttpServletRequest` (re-readable body); key `email|ip`; in-memory, single-node only.
- **Signed estimates are immutable** — mutate/delete → 409 `ESTIMATE_SIGNED`; owner-only `reopen` (live server-side, hidden behind `REOPEN_ENABLED = false`); `@Version` optimistic lock (V23); a SIGNED estimate lives only in the Економіка tab. **A signed parent is NOT auto-reopened when its duplicate is signed** — `doSign` sets `parent.countInEconomy = false` (the signature is a historical fact) and stamps `estimates.superseded_by_estimate_id` (V95); the flag clears on edit (via `requireNotSigned`, the one guard all 8 write paths share), re-sign, or dismiss.
- **Work acts (`work_act`/`work_act_item`, V104)** — built from a signed estimate's positions, signed separately; all line fields are **frozen copies**, the estimate FKs `ON DELETE SET NULL`. `WorkActService` invariants: one open (DRAFT/SENT) act per object (409 `WORK_ACT_OPEN`), a FINAL act closes it (409 `WORK_ACT_FINAL_EXISTS`), signed = immutable, delete only DRAFT/REJECTED. **Numbering is continuous per master** (`UNIQUE(user_id, number)`), so `create()` is non-`@Transactional` and retries `WorkActCreator.attempt`. **Progress is never denormalized** — Σ over SIGNED acts (`sumSignedQuantitiesByEstimateItem`) feeds the progress endpoint, `cumulative_before` and `EstimateItemResponse.closedByActs`. Off-estimate lines become a SIGNED, counted, non-shared `Estimate.kind = ADDENDUM`. **«Новий акт» creates NOTHING** — `/acts/new` is a static route, `persist()` is the one door Save and Підписати share.
- **Act portal (`ShareLinkKind.ACT`, `?a=`, V105)** — a fourth link kind, deliberately NOT folded into read-only ECONOMY (which must never let the client sign); one link = one act (`project_share_links.work_act_id` + invariant CHECK). **Defense in depth: only SENT/SIGNED are served** — a DRAFT is 404 even with a valid token. Sign records signer name/phone/ip/UA, stamps SIGNED, computes **`doc_hash` = SHA-256 of the canonical (unstamped) PDF**, and pushes + emails a copy, both fail-soft. Wording is «Підтвердити приймання робіт», never a legal-equivalence claim.
- **Works axis in economy (FREE-visible)** — `ObjectEconomyResponse.acts(contracted, acceptedByActs, received)`, computed unconditionally in `ObjectExpenseService.economy`. **INVARIANT — numerator and denominator count ONE estimate set**: `sumSignedActLineTotals` and `sumIncomeCounted` both take only SIGNED + `count_in_economy = true` estimates plus off-estimate lines (`estimate_id IS NULL`), so «Прийнято актами» ⊆ «За договором». Enforced three ways: `progress` skips `!countInEconomy`, a write guard (400 `WORK_ACT_ESTIMATE_EXCLUDED`), and both sign paths creating the ADDENDUM via the shared `ActAddendumCreator`. Never drop the `IS NULL` branch or the `count_in_economy` filter. An ADDENDUM panel carries no ⋮ (409 `ESTIMATE_ADDENDUM_LOCKED`).
- **The economy progress strip is ONE component in FOUR places (green-progress-strip)** — **colour is a POSITION, never a verdict**: the gradient spans the whole TRACK (`background-size: {(100/pct)*100}% 100%` on a `width: {pct}%` fill), so the fill is a window onto it; drop the `background-size` and you silently get the rejected hue-interpolation. 100 % is a separate solid state. The PWA's three copies are `components/ProgressStrip.tsx`; **the fourth cannot be shared** — `static/portal/index.html` (other repo) hand-copies the rule: **change one, change the other in the same commit.** `progressPct()` is **uncapped** (only the width clamps) so an overpayment can't read as «100 %». [docs/iteration-green-progress-strip.md](docs/iteration-green-progress-strip.md).
- **Act «ДОВІДКОВО» reference block (V106)** — three object-wide money rows from the same queries as the works axis via the shared `ActCumulativeCalculator`, so PDF and app never disagree. **Default OFF**, shown only from the 2nd act. The figures are live and object-wide, so the block is **excluded from the canonical (hashed) render** (`PdfModel.cumulative = null` at hash time) — a later signing must never invalidate an earlier act's stored `doc_hash`.
- **Acts follow-ups (acts-improvement, V108 `work_act.title`)** — optional `title`, frozen on sign; **owner status moves** `PATCH /api/acts/{id}/status` with the allowed set ONLY `SENT→DRAFT` / `SENT→REJECTED` / `REJECTED→DRAFT` (else 409 `WORK_ACT_BAD_TRANSITION`; `REJECTED→DRAFT` re-checks one-open-act); `ActSignedCopyService` shares the docHash stamp + client PDF email across BOTH sign paths (offline signing produced neither); `QuestionRateLimiter` covers client questions on any public portal, separate from the 30/min `PortalRateLimiter` read cap.
- **Act receipts — «Чеки та рахунки» (V110 + V111)** — materials paid out of pocket, re-billed on one act: `work_act_receipt` + `work_act.receipts_to_expenses`. **The photo is MANDATORY** (400 `WORK_ACT_RECEIPT_PHOTO_REQUIRED`); all writes are behind `requireNotSigned`; `payable` = `total` + receipts − `advanceOffset`, floored at 0. **The ⊆ invariant extends to them** — on sign they join the ADDENDUM via `ActAddendumCreator` and `sumSignedActReceipts` feeds `acceptedByActs`; add one without the other and «Прийнято актами» passes «За договором». `receipts_to_expenses` posts each as a MATERIALS/RECEIPT `ObjectExpense`. Recognition (`AiFlow.ACT_RECEIPT`, haiku) reads label/date/total only, is free, persists nothing, is capped by `ReceiptScanRateLimiter`, and is **not `@Transactional`**. **`itemized` is LEGACY and still load-bearing** — no new row gets it, but every `AND r.itemized = false` STAYS or money is billed twice. The PDF receipts block is **inside** the hashed render. **A new LLM verb must join `api/client.ts`'s long-timeout rule** or it silently aborts mid-call.
- **Fiscal QR fast path (`service/fiscal/`)** — a receipt's QR carries `fn`/`id`/`date`/`sm`, so reading it beats reading the paper with no model call. `FiscalQrService.read` is a ladder that **degrades, never fails**: no payload → not recognized; ДПС lookup unreachable → still recognized on total + date; positions not summing to `sm` within **0.02** → dropped wholesale, meta kept. `FiscalCheckXml` tolerates both `ROW`/`P` layouts and is XXE-hardened; blank `app.fiscal-qr.base-url` = lookup disabled (how tests stay off the tax service). **Everything the QR returns is FREE** — no model runs, hence `ReceiptImportService.commit` lost its `RECEIPT_IMPORT` gate. Two live-paper bugs, both below the top rung where tests never dial out: `RestClient.uri(String)` re-encodes an already-encoded URI (**build a `URI` with `.encode().build().toUri()`**), and `CHECK` reuses `<ROW>` for pay/tax rows, so positions read `CHECKBODY` → bare `<P>` → document-wide last. [docs/iteration-fiscal-qr.md](docs/iteration-fiscal-qr.md).
- **Receipts arrive as a BATCH — saved first, priced later (receipts-batch)** — `MIN_AMOUNT` is **0**, so an unpriced receipt is a legal intermediate state; what makes that safe is **`ActReceiptCompleteness.requireAllPriced` on all three doors** — publish, `signOffline`, AND `PublicActPortalService.sign` (400 `WORK_ACT_RECEIPT_UNPRICED`); the portal one is NOT redundant, since receipt writes are governed by not-SIGNED, not not-SENT. Editing is deliberately not blocked. Consequences: a blank label is named **«Чек №N» by the SERVER**; the add endpoint takes **`X-Entity-Uuid`**; **`findByWorkActIdNewestFirst`** replaces the old sort at EVERY call site so editor/PDF/portal/ADDENDUM agree on which receipt is «1.»; `…/receipts/{id}/recognize` reads the ALREADY-STORED photo; **`QrScanRateLimiter` counts the QR path apart** from `ReceiptScanRateLimiter`. PWA: no separate QR action (it is the free first rung of «додати чек з фото»), and `useReceiptBatch` saves every photo first, invalidates, then reads. [docs/iteration-receipts-batch.md](docs/iteration-receipts-batch.md).
- **Partial returns on an act receipt (V115)** — ONE number on the purchase receipt: `work_act_receipt.returned_amount` (`NOT NULL DEFAULT 0`, CHECK `>= 0 AND <= amount`); no return document, kind, photo or date. **Deliberately NOT a second `itemized`** — one billing path with a smaller number, so no money query needs a discriminator. `amount` stays what the PAPER says; everything downstream reads **`billedAmount() = amount − returnedAmount`** (`receiptsTotal`/`payable`, `sumSignedActReceipts` + `sumByWorkActId`, the posted `ObjectExpense`) — change one without the others and the bill, «Прийнято актами» and `Прибуток` disagree. The ADDENDUM list filters `billedAmount().signum() > 0`; the EXPENSE list stays unfiltered. **The cap is load-bearing** — nothing downstream goes negative, so the `>= 0` CHECKs elsewhere need no relaxation. **Same round: `work_act.advance_offset` is DOCUMENT-ONLY** — nothing in the economy reads or reconciles it, so the editor only *suggests* from `useEconomy`, non-blocking. [docs/iteration-act-receipt-returns.md](docs/iteration-act-receipt-returns.md).
- **Admin funnel's `shared` step = BOTH link tables (analytics-shared-fix)** — a **union of owner-id SETS** over `estimate_share_links` and `project_share_links` (`findSharedOwnerIds`), never a sum of two `COUNT(DISTINCT)`s. `ShareLinkKind.SHARED_WITH_CLIENT` = {PORTAL, ECONOMY, ACT} is the one classification point; **`MESSAGE` is excluded**, **`revoked`/`expires_at` are NOT filtered** (the step means "ever shared"; two pre-existing lookups carry `AndRevokedFalse`, the tempting mistake), every step filters `role = USER`, and **historical figures are understated and not comparable**.
- **By-source funnel + first-touch UTM (V114)** — the whole funnel per source, whose `shared` is **the same computation as the aggregate, not a copy** (`sharedOwnerSources()` runs once; the funnel takes `.size()`, the breakdown groups the values). **Invariant pinned by `SourceBreakdownIntegrationTest`: for every step, Σ over sources == the matching `ActivationFunnelResponse` field.** Below `SIGNIFICANT_SOURCE_MIN_REGISTRATIONS` (5, shipped as `significanceThreshold`) a row is kept but grouped under «замало даних» and excluded from rate ordering; every percentage renders with its denominator; **the SERVER owns row order**. **UTM is the CHANNEL dimension, `referral_source` the PARTNER one** — `users.utm_*` are nullable, stamped ONCE at registration, never overwritten, and **NULL is a legitimate value** rendered «без UTM» (hence the deliberate `HashMap`). PWA `captureUtmFromUrl` stores all three as one entry and stores **nothing** when there are no tags. [docs/iteration-analytics.md](docs/iteration-analytics.md).
- **PostHog is PWA-only, and the boundary is a rule (iteration-posthog)** — the admin funnel is **state-shaped**, PostHog the **event-shaped** counterpart, and it exists for **session replay**. The rule: **money and state belong to the backend — PostHog only gets what the backend does not already write** (which killed `checkout_started` and `estimate_signed`, and is why the two **dictation** events are legitimate: `parse` persists nothing, `commit` can't record that a line was dictated, so PostHog is the ONLY source there — never the spoken text, only counts). Three facts bind the repos: the **privacy policy is part of the feature**; **no personal data leaves the device** (`autocapture:false`, a fixed five-property set, a master-invented trade never travels); replay lives in PostHog only. Consent is a single door, `applyAnalyticsIdentity(me)`; **`reset()` on logout is mandatory** (a crew shares one phone). **The one BACKEND consequence is the replay→person join** — `UserRepository.idOrNull` ORs `u.id = :id` into **both** ordering queries, by **equality, never LIKE**; **`UUID.fromString` is LENIENT below 36 chars**, so `idOrNull` requires the canonical form first. [docs/iteration-posthog.md](docs/iteration-posthog.md).
- **The PWA update banner needs THREE things, any one silently kills it (iteration-sw-update-banner)** — `registerType: 'prompt'` (the shipped `autoUpdate` destructures `onNeedRefresh` and never calls it) + a `SKIP_WAITING` handler in `src/sw.ts` (`injectManifest`, so workbox-window's post must be handled by hand) + `clients.claim()` on activate (else `controlling` never fires and the tap does nothing). `src/lib/swUpdate.test.ts` asserts all three by **READING `vite.config.ts` and `src/sw.ts` as text** — the failure mode is that nothing ever appears, and every mocked test stayed green through a year of it being broken.
- **An act receipt authors offline (offline-act-receipts, PWA-only)** — the op carries the photo as **bytes, not a `Blob`** (`QueuedFile`), downscaled before queueing. Outbox entity `actReceipt`, **create only**, replayed under the same `X-Entity-Uuid` so a replay can't duplicate money in the act AND its ADDENDUM. **Editing or deleting a queued receipt is not a second op** — the pending create is rewritten in place, and both helpers answer `false` once it drained. Queued rows merge into the server list at ONE point (`ActEditorPage`), **never into the query cache**. Testing trap: `initOutbox` also subscribes to reconnects — call it ONCE.
- **Dictation is text, never audio** — `AiFlow.DICTATION` + `POST /api/estimates/{id}/dictation/{parse,commit}`; the mic is the master's own phone keyboard; we record and transcribe nothing. The 🎤 entry point is **hidden on desktop** (`matchMedia('(pointer: coarse)')`), the endpoints are not. **The rule the flow hangs on: a position matching nothing in the master's `catalog_items` comes back FLAGGED (`issues` gains `"catalog"`), never silently priced at 0 ₴.** Spoken values win, the catalog fills the blanks. **The catalog is deliberately NOT in the prompt** — the model only splits the sentence, `CatalogMatcher` decides: exact, then Dice over **4-letter** stems (Ukrainian inflects on the tail), `MIN_SCORE = 0.6` **and** `MIN_MARGIN = 0.1`, **a tie is refused**. Own hourly bucket; **the model is PINNED to `claude-sonnet-5`**. Ungated on purpose (the PRO decision now has PostHog data feeding it); `commit` goes through `appendItems`; untyped defaults to WORK. PWA: a missing unit BLOCKS the commit, a missing price only warns. [docs/iteration-dictation.md](docs/iteration-dictation.md).
- **The shopping list is where the material answer lands, and it is used with no signal (V126)** — `shopping_list`/`shopping_list_item` are OBJECT-scoped, FREE on every plan, and carry **no price** (in the shop he reads the price tag). **A norm has NO foreign key**: `catalog_items` has no link to `catalog_templates` and every catalog rebuild (V82, V116, V122) deletes and recreates the templates, so `material_norm` is keyed by **name + unit** (`NameKeys`); `trade` is **not part of the key but IS a filter on the answer** — a norm answers for a position of its OWN trade, or for anyone if it carries no trade at all (`MaterialCalculatorService#normsFor`, §25). `estimate_items.trade` is nullable by design (V125) and DERIVED from (name, type, unit); V118 filing a shared position under one trade only is what **V132 re-files**, never a reason to drop the filter. A norm's unit is read off the POSITION, never converted. `material` is a dictionary with **no price and no owner** (V81). **The list never writes an `ObjectExpense`** — money still enters only by receipt. **A recalculation replaces its OWN contribution** via `source_estimate_id`, and `clearBought` **hides** (`cleared_at`) rather than deletes, or a bought row returns unbought and the material is bought twice; `edited` does the same for a hand-typed quantity — but **not silently: V128 parks what the run would have written in `suggested_quantity`** and the master answers `suggestion: ACCEPT|KEEP_MINE` on the ordinary PATCH (so it rides the existing outbox op offline). The offer is cleared by every decision AND by the position leaving the estimate, answering a gone offer is a **no-op not a 400**, the op carries **no number** (both sides read the parked figure off the row), and `ACCEPT` clears `edited` because taking our figure hands the row back. `topUp` is derived on the read path from a settled sibling with a lower `sortOrder` — a bare «6» beside a bought 12 reads as our arithmetic slipping — which is why `render()` loads **every** row (a CLEARED row is invisible and still settled) instead of the deleted `findVisible`. Rows are deliberately **never merged** — a replayed offline create under the same `X-Entity-Uuid` would find nothing and create again. PWA: every write queues (`shoppingItem` + coalesced `shoppingClear`), and the optimistic patch updates the home card from the same write. **An unsigned source estimate is a HINT, never a gate** (master's ruling) — `sourceEstimateUnsigned` (computed in `render()`, so every path agrees) and `MaterialCalculationResponse.estimateSigned` each show one quiet line; nothing is blocked and no estimate line is locked, because he buys before he signs and a screen that refuses the tick just gets lied to. - **The calculator answers «скільки купити», and its DENOMINATOR is the interesting half (V127)** — `MaterialCalculatorService` turns one estimate's WORK lines into materials, FREE on every plan.
